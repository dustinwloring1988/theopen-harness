# @buckeyestudio/toh-client-ui-notify

[English](README.md) | 中文

回合通知插件：针对用户切走标签页后最容易错过的两种状态——回合完成、智能体被审批阻塞——弹出操作系统通知，并提供控制它们的偏好设置行。本插件是纯界面外壳：任何内容都不会进入模型请求、会话日志或 token 计数。

浏览器半端订阅会话列表快照（`ctx.sessions.list`）——侧边栏行渲染所用的同一份聚合权威数据——而非原始线路帧：每条摘要已携带 `running`、`pendingInteraction` 与"已完成但未查看"的 `completed` 位。每一趟与上一份快照对比推导出边（出现待处理交互，或 `completed` 变为真），并把每个候选事件交给覆盖四项事实的纯决策门（`shouldNotify`）：持久化模式、文档焦点、免打扰时段、Notification 权限。由于决策读取的是状态而非帧，重连基线、快照重放与多标签页回显都无法伪造出幻影事件。

去重键由实时状态派生（`<session>:pending:<status>` / `<session>:completed`），并在事实存续期间保持武装：一条弧线每页最多弹出一次通知。一个键只有在事实连续两趟缺席后才解除武装——单趟缺席恰恰就是重连代的样子——因此快照重放不会重复触发旧弧线，而下一条真正新的审批或完成事件会再次通知。OS `tag` 携带同一键，平台因此也会替换同弧线的旧通知。文档持有焦点时默认抑制通知——用户本就看着产品自己的警示圆点。

权限遵循"首次事件时询问"流程：默认模式为 `ask`，加载后第一个符合条件的事件触发浏览器授权提示——绝不会在启动时空弹。授予之后模式等同 `on`；被拒绝则静默退化为页内指示器。

## 设置表面

通用分区中的偏好行（id `notifications`）持有持久的 `ui-notify` 命名空间：`mode`（`ask`/`on`/`off`，默认 `ask`），以及可选的免打扰时段 `quietFrom`/`quietTo`（24 小时制 "HH:MM"，经 schema 校验；任一边界为空即禁用）。免打扰时段抑制一切通知——包括审批——并跟随设备本地时钟；时段可跨午夜。偏好行先把操作发布到自身 store，因此 memory 模式的组合也能在本会话看到选择，Host 文档写入在其下沉。

## Model Experience

无：通知属于浏览器界面外壳，不进入任何模型请求。

#### KV Cache effect

无：不改写历史尾部。

## Known Limitations and Deferred Work

- **拒绝后无法在产品内重新询问** —— 浏览器不提供产品内重新授权入口；拒绝后插件不再提示，侧边栏圆点成为唯一信号。
- **没有按会话的开关** —— 抑制是全局的（模式 + 免打扰时段）；选择哪些会话可以打断尚属后续工作。
