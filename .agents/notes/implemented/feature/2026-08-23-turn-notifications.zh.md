# Agent Note: Turn completion and blocked approvals as OS notifications

Status: implemented

[English](2026-08-23-turn-notifications.md) | 中文

## 问题

长回合是常态。切到其他标签页或窗口的用户只有回到页面、看到侧边栏的小圆点，才知道回合已经结束——或者更糟：智能体正因等待审批而阻塞。被阻塞的 agent 在人离开时悄悄消耗真实时间。线路层早已携带全部所需事实（整个 agent 的 `running`/`idle` 转换、待处理的审批／提问请求），客户端运行时也早已把它们聚合进会话列表，但页面之外没有任何东西把它们呈现出来；`packages/client` 中从未使用过 Web Notifications API。

## 决策

`packages/client/ui-notify`（`@buckeyestudio/toh-client-ui-notify`）是一个纯界面外壳的 client 插件，作为 web-app bundle 的 `ui-notify` 行组合进来。其浏览器半端监视 `ctx.sessions.list`——侧边栏行渲染所用的同一份聚合快照——并为两类边弹出操作系统通知：会话的 `completed` 提醒出现（回合在未查看时结束），以及 `pendingInteraction` 出现（审批／计划审阅／提问正在阻塞某个 agent）。Electron 渲染进程中的行为完全一致，因为渲染进程就是一个经由 HTTP+SSE 的普通浏览器。

一条通知是否真正弹出由三条规则决定，全部收敛到一个纯函数门（`shouldNotify`），因此逻辑可以脱离浏览器测试：

- **首次事件时询问的权限流程。** 持久化模式默认为 `ask`。浏览器授权提示只在加载后第一个携带真正新事件的趟次触发——绝不会在启动时，也绝不会针对页面打开时就已存在的基础状态。授权之后等同 `on`；被拒绝则静默退化为页内圆点。
- **状态派生的去重与重连滞回。** 去重键由实时状态派生（`<session>:pending:<status>`、`<session>:completed`），并在事实存续期间保持武装，快照重放无法重复触发。一个键只有在事实连续两趟缺席后才解除武装：单趟缺席恰恰就是重连代的样子（管理器清空并重放仍未解决的交互），因此重放的等待绝不会产生幻影的重复通知。OS `tag` 携带同一键。
- **焦点与免打扰抑制。** 文档持有焦点时默认抑制（用户正看着产品自己的警示圆点）。免打扰时段（`quietFrom`/`quietTo`，"HH:MM"，经 schema 校验，可跨午夜）抑制一切通知（包括审批），跟随本地时钟。

任何 watcher 的第一个 ready 快照只记录既有事实而不通知（SessionManager 完成提醒的先例）：重新加载进一个本就阻塞中的世界的页面既不弹提示也不弹通知，基线到达前的 `pending` 阶段也不武装任何键。设置位于插件 node 半端注册的 `ui-notify` 命名空间，通过本包同样注册的通用分区偏好行编辑（`settings.general.item`，id `notifications`）。偏好行先在本地发布手势，再等待持久化写入完成，因此 memory 模式的组合也能在本会话看到选择。这里没有任何内容进入模型请求或会话日志。

同一变更还修复了页内的对应缺口：ui-workspace 的分组头在折叠时现在携带一枚警告点和本地化的等待计数，对全部可见成员统计、与展开状态无关。

## 备选方案

- **按 issue 建议通过 `ctx.remote.$on` 订阅转发的 remote 事件** —— 否决：转发事件名单中不存在 idle 转换或待处理交互信号；状态翻转走 `host/session-status` 帧，审批走可应答的 mux 帧，二者都归运行时的连接循环所有（「消费方不读原始帧」）。会话列表快照正是这些事实的合规聚合，零运行时改动，并保持插件只读。
- **在插件加载时请求 `Notification.permission`** —— 否决：它会在 harness 还没有任何话要说之前打断每一次全新访问，而浏览器越来越倾向于丢弃与有意义的时机无关的授权提示。
- **按会话的通知开关** —— 暂缓：抑制是全局的（模式 + 免打扰时段）；逐会话选择需要独立的设置表面设计，并非解决本条记录所指时间浪费的必要条件。
- **免打扰时段内仍弹出审批通知** —— 因对称性否决：免打扰时段与其他通知一样抑制审批，审批通知只出现在时段之外，安静时侧边栏圆点仍是升级路径；想要不间断的审批通知应当禁用或缩短免打扰时段，而不是切换模式。

## 后果

- 回合完成与审批阻塞现在在标签页之外可见，堵住了静默的时间浪费；折叠分组指示器补上了同一缺口的页内一半，ui-workspace 的 README 移除了对应限制。
- 权限被拒绝后在站点设置改变前不可逆转；按浏览器契约没有产品内重新询问。
- 冷启动 RPC 预算不受影响：scope 派生自 ui-settings 的共享 describe 镜像，不新增线路读取。
- 验证：纯门与控制器规格覆盖决策矩阵、边检测、去重弧线、滞回与权限握手；apply 规格钉住注册／采纳／手势布线；`apps/web/tests/settings-chrome.e2e.ts` 黄金文件覆盖组装表面上新的通用分区行。
