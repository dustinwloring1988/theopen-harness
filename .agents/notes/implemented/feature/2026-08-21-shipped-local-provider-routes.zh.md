# Agent Note: The adapter ships provider routes beside the installed pi-ai catalog

Status: implemented

English | [中文](2026-08-21-shipped-local-provider-routes.md)

## Problem

可配置提供方目录此前只提供两类路由：已安装 pi-ai catalog 所描述的，以及设置文档已经声明过的。运行本地 Ollama 服务器的用户没有得到第一类答案。可行的路径是手工声明一条自定义路由——自己发明路由键、把端点、协议和模型列表敲进创建卡片——而模型页本就把"挑选已知提供方"和"声明未知提供方"设计成两个不同的动作，于是一个常见的本地部署完全落在手工一侧。

并没有东西因此损坏：手工声明路径今天就能接上 Ollama。但选择器列出了三十七个 catalog 提供方，却列不出许多部署本来就在运行的本地服务器；构建提供哪些提供方是产品面的事，不该让设置文档为一个众所周知的场景去发明。

## Decision

`toh-llm-pi-ai` 中的 `SHIPPED_ROUTES` 记录适配器在已安装 catalog 之外提供的路由。目前只有一条：`ollama`，显示为 "Ollama (Local)"。`directoryEntries()` 把自带路由排在 catalog id 之后、profile 声明的路由之前，并携带 `declared: true`：pi-ai 在这个键下没有条目，所以该路由仍然需要只有配置能给出的内容——协议和模型——走的手工声明路由相同的编辑卡片，包括端点探测：无凭据即可从 `/v1/models` 列出本地服务器的模型。

条目还携带配置界面在无存储内容时预填的信息：端点建议（`http://host.docker.internal:11434/v1`，这样无论浏览器由本机还是由同主机上的容器提供服务都能到达服务器），它作为 `LlmConfigurableProvider` 上可选的 `baseURL` 沿目录契约传递。模型页的添加卡片由此暴露出第二个缺口：它从未把目录的 `declared` 回答转发给自己的编辑卡片，导致采纳一条声明路由时渲染的是 catalog 风格的卡片，连身份字段都没有。卡片现在会转发它，并且一次采纳从创建卡片的起点开始——声明字段展开、首个线协议预选、建议端点就位，且每一项都可编辑。

解析参与这个决定的另一半：未存 `displayName` 的 profile 先默认到自带的名称，再回落到路由键，这样选择器给出的选项在采纳之后仍然是 "Ollama (Local)"，而不是退回裸 id。已安装 catalog 同样描述的键不会进入这张映射的消费者——catalog 成员关系仍是"pi-ai 携带什么"的唯一答案——而 profile 里显式写的 `displayName` 在任何地方都胜过自带名称。被采纳的模型默认以自己的 id 作为显示名，卡片上如此，所有选择器中也如此，因为本地清单只披露 id；名称字段直接显示这一默认值，而不是看起来像缺了东西。

这条路由不附带任何凭据。本地 Ollama 不做认证，而在未配置引用时适配器自己的 api-key 方法解析为不带签名的请求——与端点探测同一姿态——所以把密钥字段留空得到的是一台可用的提供方，而不是一次延后的失败。

## Alternatives considered

- **在上游把 Ollama 加入 pi-ai 的内置提供方。** 这样它会成为真正的 catalog 路由，端点、协议、模型全部由安装条目默认。它落败是因为 catalog 条目必须携带模型 catalog——id、上下文窗口、输出上限——而本地模型清单随每一次拉取都在变，这些元数据到手即过时，还得有人永远维护下去。本适配器需要的只是"提供"和 settings 地址；用户自己的服务器才是权威的模型清单。
- **在解析层默认该路由的 `baseURL`**，让 profile 可以完全省略端点。那会让一份填了一半的 profile 注册出一条指向标签所暗示地址的路由；因此建议放在上一层——预填但可编辑——而跳过它的采纳仍在写入处被拒绝。
- **给 `LlmConfigurableProvider` 加一个通用的 hints 机制**，让目录条目携带任意编辑器默认值。可选的 `baseURL` 是今天唯一有消费者的字段；契约的进一步拓宽等到第二条出现再说。
- **在被采纳的模型行上存储 `name: <id>`。** 显示回落不需要存储：解析本就以 id 命名无名模型，卡片显示回落值即可，profile 不必保存重述的数据。

## Consequences

提供方选择器多出一个闲置时零成本的休眠选项：没有 profile 就没有注册的路由，`providerUsable()` 保持 false，其他快照钉住的首启姿态不变。采纳该选项如今是一条短路径——选中、从预填端点拉取模型清单、采纳模型行、保存——而保存与其他手工声明路由一样经过分节 schema 校验。显示名的默认顺序变为 profile → 自带名称 → 路由键，未来任何自带路由免费继承这个三步次序。

接受一处词汇成本：对一条*适配器*确实提供的路由，`declared` 回答的仍是"pi-ai 在此键下什么都没有"，于是采纳后该行会带上自定义标记。这是准确的——路由的一切确实都由 profile 携带——而替代方案是为一个没有消费者提出的区分增加第三个标志位。

## Testing

包测试钉住目录条目（存在、`declared: true`、自带名称、建议端点）、存入不带 `displayName` 的 profile 后名称保持不变，以及解析层回落与既有路由键默认并列。客户端测试从选择器驱动完整采纳流程——折叠区展开且协议与端点已预填、对草稿做端点探测、以三个路径操作存入无凭据 profile——外加已存储路由保持折叠的姿态，以及无名行的"以 id 为显示名"回落。web e2e 金标准对着装配出的应用录制：两个选择器把该选项列为 "Ollama (Local)"，声明路由编辑器金标准显示无名模型行以其 id 显示。
