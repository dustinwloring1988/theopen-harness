# Agent Note: 后端打开时清扫崩溃遗留的暂存临时文件

Status: implemented

[English](2026-08-23-crash-orphaned-staging-temp-sweep.md) | 中文

## 问题

三个持久化层面都只在成功路径或捕获错误后清理自己的暂存临时文件：JSONL 会话后端在链接或无覆盖重命名之前，把 `session.jsonl[.zstd].<random>.tmp` 写在最终日志旁；本地附件存储把暂存对象硬链接出 `attachments/v1/tmp/<uuid>`，之后再 unlink 暂存副本；请求图片缓存用 `<hash>.<uuid>.tmp` 重命名覆盖其缓存条目。在临时写入与发布之间发生崩溃或断电，文件就会永久滞留。仓库中从来没有任何清扫逻辑处理这些名称，残留只能靠手动删除；而发现机制只读取目录和固定的工件名，这些散落文件同样不可见。

## 决策

每个后端挂载时通过类插件的 `[Service.init]` 生命周期钩子执行一次尽力而为的清扫。JSONL 后端删除根目录下每个会话目录内修改时间早于本进程启动的所有 `*.tmp` 文件。附件存储以同一规则一次遍历清理它的两个层面：私有 `tmp/` 暂存目录中的条目，以及请求图片缓存对象旁的所有 `*.tmp` 文件。

一个判据统辖全部三个层面。已发布工件永远不带暂存名或 `.tmp` 名，因此删除绝不会触达它，但名称本身无法证明写入者已死：共享根目录的另一存活进程可能持有任意年龄的发布途中临时文件。每个后端在自己的挂载时刻尚未创建任何文件，因此本次清扫收集的是修改时间早于本进程启动（`performance.timeOrigin`）的候选文件；该判据不能证明写入者已退出；在那之后才滞留的孤儿即使写入者已死，也留待下次挂载。清扫只触碰普通文件和符号链接叶子（按链接本身删除，绝不跟随），跳过目录，不碰非匹配名称。

清扫失败绝不导致 open() 失败：清除了内容的成功清扫由生命周期钩子以 debug 记录数量，枚举失败在钩子中以 debug 记录错误且不含清扫数量，单文件删除失败则被静默跳过以免一个被锁文件掩盖其余条目。幸存的文件都会在下次启动重试。

## 已考虑的替代方案

**按名称无条件删除候选。** 否决：并发进程正在写入的暂存文件会在写入与链接之间消失，使一次原本正常的发布流程失败。mtime 保护把收集范围限定在明显早于本进程的文件。

**只对附件 `tmp/` 施加年龄保护，兄弟 `*.tmp` 文件凭名称直接清扫。** 否决：`.tmp` 后缀证明的是候选永远不会成为已发布工件，而不是它的写入进程已经死亡；只保护一个层面却无条件清扫兄弟文件，会让 JSONL 实体化和请求图片发布暴露在 `tmp/` 保护本已防住的同一存活进程竞态之下。统一的年龄保护让所有层面处于同一安全水平。

**清扫方与发布方共享跨进程锁协议。** 推迟：锁自带新的失败模式（崩溃的写入者留下滞留锁），需要触碰每一条关乎持久性的关键发布路径，并超出本次清理的尽力而为契约；年龄保护加上各层面自愈的丢失路径，把残余窗口限定在横跨本进程启动窗口停滞的对端。

**周期性后台清扫器或共享工具包。** 否决：残留按存储根目录累积，因此在拥有它的后端打开时清扫一次，把工作限定为每次挂载一次小型目录遍历，无需定时器、跨包依赖边或后端间协调。

## 验证

两个包的测试在真实的已发布 JSONL 日志旁和准备好的附件根内植入孤儿临时文件，然后断言陈旧候选消失，而新鲜候选（模拟另一写入者的在途临时文件）、日志、已存储对象、缓存变体、非匹配文件和范围外位置逐字节保留。其他测试覆盖单条目失败隔离（一个被锁文件不掩盖其余条目）、枚举失败向调用方传播、清扫拒绝时挂载仍然成功，以及文档化的日志分工：成功的清扫以 debug 记录数量，被拒绝的清扫记录错误而不含数量。两个包的既有套件全部不变通过。

## 后果

崩溃遗留的暂存文件由在本文件写入之后启动的第一个进程挂载时收集，而不是无限累积。本进程启动窗口内写入的残留会等待下次挂载，而不是与并发写入者竞争。若存活对端的临时文件仍在发布途中，且被清扫删除——仅当该文件早于本进程启动时才可能——丢失的 JSONL 实体化会在协调器中重新保留批次并在下次 flush 重试，请求图片生成只需重写缓存条目，附件保存则以存储错误失败一次；已提交数据不受影响。清扫在每次挂载时运行，包括短命进程，成本是两级目录 `readdir` 加每个候选一次 `lstat`。
